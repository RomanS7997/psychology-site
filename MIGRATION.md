# Переезд на julialyapina.ru

Что сейчас: сайт собран и лежит на `https://romans7997.github.io/psychology-site/`.
На `julialyapina.ru` работает старый сайт — статическая выгрузка WordPress
из шаблона для ремонтной фирмы (в меню остались якоря `#bathroom`,
`#interiordecorating`). У него четыре адреса и один и тот же заголовок
«Психолог Юлия Ляпина» на всех страницах.

В коде всё готово: домен нигде не прописан строкой, он приходит переменными.
Переключение — четыре шага, порядок важен.

---

## Шаг 1. DNS у регистратора домена

Домен должен показывать на GitHub Pages. В панели регистратора (там, где куплен
julialyapina.ru) заменить записи:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | romans7997.github.io |

Старые A-записи (на нынешний хостинг с nginx) — удалить.
Обновление расходится от 10 минут до нескольких часов.

**До этого шага остальное делать нельзя:** пока DNS смотрит на старый хостинг,
GitHub не выпустит сертификат, и сайт откроется с предупреждением о
небезопасном соединении.

## Шаг 2. Переменные в репозитории

GitHub → репозиторий `psychology-site` → Settings → Secrets and variables →
Actions → вкладка **Variables** → New repository variable:

| Имя | Значение |
|-----|----------|
| `SITE_URL` | `https://julialyapina.ru` |
| `SITE_BASE` | `/` |

Больше ничего менять не нужно: сборка сама подставит домен в канонические
адреса, карту сайта, robots.txt и разметку Schema.org, а файл `CNAME`
допишет в корень сайта.

## Шаг 3. Запустить сборку

GitHub → вкладка Actions → workflow «Deploy to GitHub Pages» → Run workflow.
Через пару минут Settings → Pages покажет домен `julialyapina.ru`.
Там же поставить галочку **Enforce HTTPS** (появляется, когда GitHub выпустит
сертификат — обычно в течение часа после того, как DNS разошёлся).

## Шаг 4. Проверить

- `https://julialyapina.ru/` — открывается новый сайт, замок в адресной строке
- `https://www.julialyapina.ru/` — перебрасывает на адрес без www
- `https://julialyapina.ru/about/index-1.htm` — перебрасывает на `/about/`
- `https://julialyapina.ru/robots.txt` и `/sitemap.xml` — отдаются
- `https://romans7997.github.io/psychology-site/` — перестанет работать, это нормально

## Старые адреса

Старый сайт жил на четырёх адресах. Серверного перенаправления на GitHub Pages
нет, поэтому сборка кладёт на старые адреса страницы-заглушки: человека
перебрасывает мгновенно, поисковику они говорят `rel=canonical` на новый адрес.

| Старый адрес | Новый |
|--------------|-------|
| `/index.htm` | `/` |
| `/about/index-1.htm` | `/about/` |
| `/contact/index-1.htm` | `/contact/` |
| `/services/index-1.htm` | `/services/adult/` |

Список задан в `scripts/build-sitemap.mjs` → `REDIRECTS`.

## После переезда

1. **Яндекс.Вебмастер** и **Google Search Console** — добавить сайт, подтвердить
   права, отправить `https://julialyapina.ru/sitemap.xml`.
   Подтверждение обычно просят мета-тегом: его вставлять в
   `src/layouts/Layout.astro`, в `<head>`.
2. **Яндекс.Бизнес** — карточка кабинета с адресом и часами. Для местного
   поиска («психолог Одинцово») это даёт больше, чем что-либо на самом сайте.
3. **Ключ Яндекс.Карт** — на странице контактов стоит заглушка `YOUR_API_KEY`.
   Карта при этом рисуется (проверено), но работает на птичьих правах: Яндекс
   вправе ограничить показы без ключа. Ключ бесплатный, берётся в кабинете
   разработчика Яндекса, менять одну строку в `src/pages/contact.astro`.
4. Старый хостинг не отключать недели две — на случай отката.
